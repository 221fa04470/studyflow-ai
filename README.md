# StudyFlow AI

Paste notes or type a topic, and get back a set of interactive flashcards
(3D flip cards) and a scored multiple-choice quiz with a "retest wrong
answers" loop — generated by an LLM.

Not a chatbot: the model is prompted to return a strict JSON shape, which
the backend validates before the frontend ever touches it, and the frontend
normalizes again defensively before rendering. That JSON becomes real,
stateful React UI — flip-through flashcards and a scored quiz — never raw
model text in a chat bubble.

## Stack

- **Frontend:** React (Vite), hand-written CSS (no UI framework) — glass
  surfaces, CSS 3D transforms for the flip card, floating decorative shapes,
  full `prefers-reduced-motion` support.
- **Backend:** Node + Express, proxies requests to Groq's chat completions
  API. The API key never reaches the browser.
- **Model:** Groq `openai/gpt-oss-20b` by default (swap via `GROQ_MODEL` in
  `.env`). Note: `llama-3.1-8b-instant` was deprecated by Groq in mid-2026 —
  if you see a `model_not_found` error, your `.env` is pointing at an old
  model name; update `GROQ_MODEL` to a currently active one from
  `console.groq.com/docs/models`.

## Setup

### 1. Backend

```bash
cd backend
npm install
cp .env.example .env
# edit .env and add your Groq API key (free tier: https://console.groq.com)
npm start
```

Runs on `http://localhost:8787`.

### 2. Frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Runs on `http://localhost:5173` and proxies `/api/*` to the backend (see
`vite.config.js`).

Open `http://localhost:5173`, type a topic or paste notes (or click one of
the example prompts), and generate.

## Component architecture

```
App
├── BackgroundDecor        (decorative floating 3D shapes, aria-hidden)
├── StudyInput              (hero + glass textarea + generate button)
│   └── ExamplePrompts
├── EmptyState
├── LoadingState
├── ErrorState
└── StudyDashboard
    ├── FlashcardDeck
    │   └── Flashcard       (3D perspective flip card — front/back faces)
    ├── Quiz
    │   ├── QuizProgress
    │   ├── QuizQuestion
    │   └── QuizResult
    │       └── RetestWrongAnswers
```

State lives in the closest component that needs it: `App` owns the
request lifecycle (idle/loading/error/ready), `FlashcardDeck` owns the
current card index, `Quiz` owns the round/score/wrong-answer state. No
external state library.

## How bad model output is handled

This was the focus of the assignment, so a quick rundown:

- **Malformed / non-JSON output:** the backend tries a direct `JSON.parse`,
  then falls back to extracting the outermost `{...}` block (models
  sometimes wrap JSON in markdown fences or add a sentence before/after it).
- **Wrong shape:** a `validateShape()` check on the backend confirms every
  field exists, `flashcards`/`quiz` are non-empty arrays, each quiz question
  has exactly 4 options and a valid `correctIndex`, etc.
- **One repair attempt:** if the first response fails parsing or
  validation, the backend sends it back to the model with a short "your
  JSON was invalid, fix it" follow-up and tries once more before giving up.
- **Still bad after retry:** the backend returns a `502`. The frontend
  shows a designed error state ("Something went wrong" / "We couldn't
  generate your study material. Please try again.") with a **Try again**
  button — never a raw stack trace or API error message by default (the
  technical detail is available behind a collapsed "Technical details"
  toggle for debugging, not shown up front).
- **Frontend never trusts the shape either:** `StudyDashboard` normalizes
  and filters the data again before rendering (drops any malformed
  flashcard/quiz entry) so a gap between backend and frontend expectations
  can't crash the component tree.
- **Slow / hung requests:** the backend aborts the Groq call after 20s and
  returns a `504`, surfaced as the same error state.
- **Stale responses:** if the user submits a new prompt while a previous
  request is still in flight, the old request is aborted and its result is
  discarded via a request-id check in `App.jsx`, so a slow old response can
  never overwrite a newer one on screen.
- **Empty input:** the generate button is disabled until there's
  non-whitespace text; the backend rejects empty `input` with a `400` as a
  second line of defense.

## Design notes

- Dark, layered "AI product" aesthetic: deep indigo background, glass
  surfaces (`backdrop-filter: blur`), a violet→cyan gradient as the primary
  accent (never a single flat neon), coral reserved for the quiz
  retest/wrong-answer accent only.
- Display type is Space Grotesk (headline, topic title, card text), body
  is Inter, and IBM Plex Mono is used only for small counters/eyebrows
  ("Card 1 / 8") for a data-y, technical feel.
- The flashcard is the signature interactive element: real 3D
  (`perspective`, `transform-style: preserve-3d`, `rotateY`,
  `backface-visibility: hidden`), flips on tap/click/Enter/Space, and
  supports `←`/`→` keyboard navigation between cards.
- All motion respects `prefers-reduced-motion` (floating background
  shapes and transitions are disabled for users who request it).
- Responsive from 320px up: tabs and controls stack, decorative shapes
  shrink/dim on small screens, buttons go full-width where needed.

## Known limitations

- No streaming — the full result is generated before anything renders.
- No session persistence — refreshing the page clears the generated
  material.
- The repair retry only fires once; if the model is badly broken twice in
  a row, the user has to hit "Try again" manually.
- No dark/light mode toggle — it's dark-only by design (matches the
  requested premium AI-product aesthetic).

## What I'd do next with more time

- Stream the response token-by-token and render flashcards as they arrive.
- Persist sessions to `localStorage` so a refresh doesn't lose material.
- Let the model return mixed block types (e.g. a summary card alongside
  flashcards/quiz) and render each block type differently.
- A refinement loop ("make it harder", "add 5 more cards") that edits the
  existing result instead of regenerating from scratch.
